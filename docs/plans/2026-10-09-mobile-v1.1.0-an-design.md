### 1.2 字体

- **正文/标题**：系统无衬线栈（Android `Roboto`、iOS `Helvetica Neue`），靠**字重与字距**制造编辑感：标题 700 / -0.035em，正文 500 / -0.01em。
- **mono 层**：Android `monospace`（等宽）用于：kicker、编号、计数、tag、tabs、sheet 标签，`letter-spacing .10–.22em`、全大写。
- 不引入任何 web 字体（离线可用、零启动开销）。

### 1.3 布局与间距

- 4px 基准网格；页面水平 padding 24px。
- **hairline 体系**：分区标题下 1.5px ink 实线，行间 1px `line`；不使用卡片、圆角（最多 2px）、阴影——唯一的硬阴影留给 FAB（`6px 6px 0 ink`）。
- 原型中的 32px 竖栏网格背景**降级不做**（RN 无低成本等价物，hairline 分隔已足够表达栏位感）。

## 3. M1 · HTTP 同步桥（详细设计）

### 3.1 云端服务（`services/sync-bridge`，ECS 直跑 systemd，无 Docker）

- Node（与仓库同版本），监听 `0.0.0.0:<port>`；安全组仅放行该端口。
- 鉴权：`Authorization: Bearer <token>`，token 为 32+ 字节随机串，存服务器 `.env` 与手机设置页（**手动输入配对**，桌面端不参与 HTTP）。
- 存储：`/var/lib/hengsch/sync.json` —— **与桌面 SFTP 路径同一个文件**。
- 路由：
  - `GET  /sync` → `200 { etag, state }`；`state` 即 sync.json 原文
  - `PUT  /sync?etag=<n>` → 校验 etag 匹配后原子写（tmp+rename）→ `200 { etag: n+1 }`；不匹配 → `409 { etag }`
  - `GET  /health` → `200 ok`（无鉴权，供监控）
- etag = 文件 mtime+size 派生或内存单调计数（重启后以文件内容 hash 起底）。
- 桥**不解析** state 内容；合并逻辑只在客户端。

### 3.2 手机端 `SyncContext`

- 触发：启动、`AppState` 回前台、每 60s、手动下拉。
- 流程：`GET /sync` → 本地 `mergeSyncStates(本地, 远端)`（复用 `@hengsch/shared-logic`，经 `sync-shared.js` 副本进 `v1.1.0-an/shared/`）→ 若有变化 `PUT`（带 etag）→ 409 则重读重合（最多 3 次）→ 写回本地存储。
- 状态机与桌面一致：`SYNCED / OFFLINE / AUTH ERROR / REMOTE ERROR`；错误不覆盖本地数据，footer 显示状态。
- `deviceId`：首次启动生成 uuid，存 AsyncStorage；**所有新写记录必须 `fillSyncMeta()`**——当前 `an` 的 `TodoContext.addTodo` 缺 `updatedAt/deviceId`，M1 第一步对齐 `shared-logic`。
- 范围：仅 todos + groups；设置项（如监测阈值可挂哪类任务）各端独立——与桌面决策 8 保持一致。

### 3.3 冲突与一致性

- 两端（手机 HTTP / 桌面 SFTP）都做 read → merge → write；同文件即真相。
- merge 是 LWW（`updatedAt` + `deviceId` 平局）+ tombstone 幂等，已在桌面 Phase 0-3 验证。
- 窗口风险：两设备同时写（etag vs SFTP 无锁）——概率极低，后果是后写者基于旧读覆盖前写的已合并结果；下轮 sync 时 LWW 会恢复正确状态（记录不丢，仅可能延迟一轮）。**接受**。

### 3.4 M1 验收（5 条）

1. 手机新增/完成 → 桌面 60s 内出现（反向同理）。
2. 双端离线各改同一条 → 重连合并后 LWW 正确、无重复行。
3. tombstone（如 `remote-b-test`）在手机端删除后不复活。
4. token 错误 → 手机 `AUTH ERROR`、不写回；修正后恢复。
5. 云端 bridge 挂掉 → `OFFLINE`；重启后自动追平。

## 4. M2 · UsageStats 监测（按平台重写计算，字段共享）

- **权限**：`PACKAGE_USAGE_STATS`（用户到系统设置手动授予"使用情况访问"）；App 内引导页 + 权限状态检测。
- **采集**：前台服务（`FOREGROUND_SERVICE` + `foregroundServiceType="specialUse"`，Android 14+），每 30s `UsageStatsManager.queryEvents(上次查询点, now)`，取目标包名（`monitor.exeName` → 包名，如抖音 `com.ss.android.ugc.aweme`）的 `MOVE_TO_FOREGROUND/BACKGROUND` 区间累计。
- **与桌面算法差异**：桌面是"存在即计时 + 单步封顶 180s"（进程粒度、轮询粒度）；手机有**精确事件区间**，按区间直接累加，无 30s tick 封顶（tick 只是查询节奏，区间起止来自事件时间戳）。跨天/`checkpointAt` 推进/`notified` 一次性达标逻辑与桌面保持同构。
- **存储**：`monitorProgress` 键 `${todoId}:${YYYY-MM-DD}` 共享字段，存 AsyncStorage；7 天清理。
- **回溯**：冷启动查"今日 0 点 → now"一次（UsageStats 保留期足够）；达标 → 标记完成 + 本地通知，复用共享 `shared-logic`。
- **范围**：同桌面，仅循环任务可挂监测。

## 5. M3 · Widget + 通知快捷完成

- 工程：`expo prebuild`（或 dev build），原生代码 Kotlin。
- **Widget**（AppWidgetProvider + RemoteViews）：列表（≤5 条 active）+ 勾选即完成。
  - 数据桥：RN 侧每次状态变化把精简快照（id/title/done）经原生模块写入 SharedPreferences，Widget 只读原生层（不依赖 JS 存活）；勾选动作由 BroadcastReceiver 直接改 SharedPreferences 并回灌 RN 合并。
- **通知**：监测达标通知（同桌面语义）+ 常驻"今日进度"通知带**快捷完成 action**（`PendingIntent` → 同上回灌通道）。
- AppWidget/通知的完成操作统一走"写本地 + 触发 SyncContext 立即 sync"。

### 验收中确认的语义与修复

- **位移盖章（非 bug）**：桌面 `TOGGLE_TODO_STATUS` 对排序位移的记录重盖 `updatedAt/deviceId`（order 变化视为内容变化，整记录 LWW）。表现：一条设备新增的待办在另一设备被排序位移后，deviceId 会变更为位移方。两端行为对称、收敛一致，按设计接受。
- **Android 明文 HTTP**：Android 9+ 默认禁 `http://`，同步桥无 HTTPS → `app.json` android `usesCleartextTraffic: true`（**app.json 为源**，`expo prebuild` 会覆盖 `AndroidManifest.xml`，改配置须两处同步或重跑 prebuild）。
- **桌面两个 bug（随验收修复）**：① 页脚同步入口 `state !== 'OFF'` 条件移除（OFF 时打不开设置的死锁）；② `readRemoteFile` 将 ssh2 SFTP 错误码 `2 (NO_SUCH_FILE)` 与 `'ENOENT'` 等同视为远端无档（此前首传永远走不通）。
- **设置页 UX（用户反馈）**：「测试连接」通过即自动保存（失败不落盘）；「立即同步」先保存表单再触发同步。
- **验收残留**：云端遗留 `验收A-手机新增`、`验收E-桥停期间新增` 两条可见待办及若干测试墓碑（30 天后自动清除）。
