## 4. 批次四：新报障与需求（2026-10-25 用户报障）

### B-1 抽屉会话不保留 + 终态卡占地方
- **现象**：关抽屉/重开（或重启）后只剩卡片，对话文字没了。
- **现场初判**（已读码）：`App.tsx:280` 抽屉常驻挂载、`flow` 为内存 state；卡片能回来走 `mergeRestoredQueue`（主进程队列），文字只在内存 → 优先怀疑**应用重启/重载路径**，关/开抽屉本身不应丢。
- **步骤**：先复现定路径（A 关开抽屉 / B 重启应用）→ 对症修：A 找重挂载点；B 对话文本持久化恢复（存本机、挂载回填，与队列恢复同链路，`新会话`同步清持久化）。
- **B-1.2 终态卡折叠（D-C 翻案）**：已创建/已取消卡缩成一行摘要（标题+状态），点开可展开；待确认卡照旧。
- 验收：重启后文字+卡片都在；终态卡一行、不占地方。

### B-2 多条删除接续 + 批量确认【方案 B：合并一卡】
- **现象**：多条删除时，确认一张后下一张删除卡不冒出来。
- **步骤**：复现（一次 stage ≥3 条删除 → 逐张确认）→ 查 `commitCard→showNext` 链、队列 TTL、D-2 闸门是否误拦。
- **实现（方案 B）**：多条删除提案合并为**一张清单卡**（逐条勾选 + 一次确认/跳过）；倾向渲染层合并（不改模型工具语义），落地时定。
- 验收：3 条删除 → 一张清单卡 → 勾选确认 → 全部落盘 + `完成 N · 跳过 M` 系统行；未勾选可跳过。

### B-3 语音提速：SenseVoiceSmall spike
- 现状：whisper small-q5_1 已 `-t 8`（11s 夹具 8s→5s），仍是 CPU 自回归推理。
- **方案**：SenseVoiceSmall（非自回归、中英日韩粤+标点）**whisper-cli 跑不了**，需引入 **sherpa-onnx** 运行时。
- **步骤**：① Spike：sherpa-onnx Windows x64 CLI + 模型下载（URL+sha256、hf-mirror），用 `scripts/fixtures/jfk.wav` 实测耗时/出字对比 whisper；② 集成设计：`voice-service` 抽后端选择、AI 设置加模型下拉（whisper-small / sensevoice-small 双后端、默认 whisper）；③ 核实打包体积与许可；④ 门禁 + A/B 计时入证据。
- **决策点**：spike 数据出来后拍板——双后端共存 or 替换。
